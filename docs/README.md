# Documentation

An index of this folder, grouped by purpose. The authoritative orientation
file is [`../AGENTS.md`](../AGENTS.md) (one level up, at the repo root) — read
that first.

## Reference (top level)

- [`command_reference.md`](command_reference.md) — every serial command, SCPI
  matching rules, error codes.
- [`serial_reflash_guide.md`](serial_reflash_guide.md) — the `BOOT`/`stm32flash`
  reflash mechanism, the VTOR/MEMRMP fix, troubleshooting.
- [`test_protocol.md`](test_protocol.md) — numbered bench test protocol (T0–T4).
- [`pin_mapping_reference.tex`](pin_mapping_reference.tex) / `.pdf` — curated
  pin-role reference (per-channel XREX naming, polarity, simulator wiring).
- [`pin_mapping_v4.csv`](pin_mapping_v4.csv) — the authoritative raw pin data
  the reference above is derived from.
- [`sop/`](sop/) — formal build/flash/verify Standard Operating Procedure (LaTeX).
- [`Transrex/`](Transrex/) — vendor/spec PDFs (Transrex ISR-2126 controls
  upgrade, HRTIM divergent-period timing).

## History

- [`changelog.txt`](changelog.txt) — running dated change log with root causes.

## Generated reports ([`reports/`](reports/))

Regenerated by the Python tooling — do not hand-edit. Older reports here are
flat files directly under `reports/`; every new `.tex` report project gets
its own well-labeled subdirectory under `reports/` instead (2026-09-22
convention, see below):

- `simulator_validation_report.tex` / `.pdf` — discrete scenario results
  (generated by `python/run_simulator_validation.py`).
- `simulator_channel_matrix_report.tex` / `.pdf` — 45-shot channel/demand
  matrix results (same script, `--matrix`).
- `memory_report.html` + `memory_history.csv` — flash/RAM footprint history
  (generated by `python/memory_report.py`).
- [`gain_smoothness_sweep/`](reports/gain_smoothness_sweep/) — closed-loop
  Kp/Ki sweep ranking commanded-output smoothness
  (`gain_smoothness_sweep_report.tex` / `.pdf`, generated by
  `python/run_simulator_validation.py --gain-smoothness`).

## Campaigns ([`campaigns/`](campaigns/))

- `test_campaign_plan.md` — the planned campaign (scenarios, parameters, pass
  criteria).
- `test_campaign_report.md` — the 10 s / 5 s campaign setup, smoke-test run,
  and review points.
- `test_campaign_results.md` — **full campaign results**: per-test parameters,
  pass/fail, embedded plots, and a comment on what each test accomplished.
- `campaign_report.md` — detailed results report: a paragraph per test (what ran
  and why it passed/failed) plus a 4-panel plot for each.
